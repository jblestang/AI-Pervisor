## Domain expert notes

### Transfer ABI

- **Finding:** Hypervisor UEFI entry previously sized the transfer slice from `header.total_size` only; loader publishes into page-rounded runtime memory that may exceed `total_size`.
- **Fix:** Transfer ABI v2 adds `published_alloc_size`; loader calls `patch_published_alloc_size()` after copying into `RUNTIME_SERVICES_DATA` pages; `validate_transfer_bounds()` rejects inconsistent fields.
- **Risk (deferred):** No runtime integrity seal over the transfer blob beyond layout/digest checks; tampering after publish remains a firmware-trust concern for Gate C+.

### Requirements snapshot

- **Finding:** VMX init planning needs static layout metadata (`hypervisor_reserve` phys/size) that was only available on the host compile path before Phase 9.
- **Fix:** `RequirementsSnapshot` embeds `hypervisor_reserve_phys` / `hypervisor_reserve_bytes`; `requirements_snapshot_from_platform()` and `platform_requirements_from_snapshot()` round-trip under bounds checks.
- **Risk (deferred):** Snapshot still omits `partition_id` and device `kind` strings; PCI validation uses BDF + vm_id only.

### VMX foundation (`hv-vmx`)

- **Finding:** Gate B requires a VMX init seam before hardware enablement; UEFI and host paths must share planning logic without pulling in VMX instructions yet.
- **Fix:** `plan_vmx_init()` validates reserve alignment/size; `init_vmx()` gates on validated VMX/EPT observation; `MockVmxBackend` records plan execution for host and firmware tests.
- **Risk (deferred):** No VMXON, VMCS, EPT paging, or VT-d programming — mock backend only until Gate C.

### Hypervisor boot split

- **Finding:** Gate B orchestration lived in `hv-hypervisor` with dependencies unsuitable for `no_std` UEFI consumers; feature unification from build-deps previously pulled `std` into firmware images.
- **Fix:** Extracted `hv-hypervisor-boot` (`no_std` + `alloc`); `hv-hypervisor` re-exports for host tests; hypervisor embedded config generated by host `tools/hv-config` (mirrors loader digest pattern).
- **Risk (deferred):** `hv-hypervisor-boot` still depends on `hv-config-model` / `hv-platform-model` with careful feature gating; future Gate C hardware code must preserve this split.

### UEFI hypervisor entry

- **Finding:** Phase 8 hypervisor firmware verified transfer structure and digest only; Gate B closure requires the same fail-closed platform compare as the host boot path.
- **Fix:** `boot_hypervisor_from_transfer()` delegates to `boot_from_transfer_and_init_vmx()`; firmware logs structured errors on failure and `hypervisor Gate B boot succeeded` on success.
- **Risk (deferred):** Error strings are logged via UEFI logger only; no persistent telemetry channel.

### Build / CI / OVMF smoke

- **Finding:** Production `configs/qemu.yaml` requires VMX/EPT/VT-d/NX and reference PCI BDFs that TCG-backed OVMF/QEMU cannot satisfy; Phase 8 smoke only checked for boot attempt, not Gate B success.
- **Fix:** Added `configs/ovmf-smoke.yaml` (optional hardware features, no expected PCI devices); `cargo xtask ovmf-smoke-boot` defaults to this config, uses `-m 8192` and `-smp 4`, and accepts serial log without `failed to start Boot`. Production Gate B + mock VMX init remains host-tested with `configs/qemu.yaml`.
- **Risk (deferred):** Full production-requirement OVMF boot still requires KVM (or bare metal) with guest CPUID exposing VMX; not exercised in TCG CI today.

## Findings and disposition

### MUST FIX (applied)

1. **Transfer ABI v2** — `HypervisorTransferHeader` gains `published_alloc_size`; loader publish patches allocation size; hypervisor validates bounds against slice length.
2. **Gate B on UEFI** — `hv-hypervisor-efi` runs `boot_from_transfer_and_init_vmx()` (observe, validate, plan VMX, mock backend init) instead of transfer/digest-only verification.
3. **VMX foundation crate** — `hv-vmx` provides `VmxInitPlan`, `plan_vmx_init()`, `init_vmx()` with `MockVmxBackend` for host and firmware paths.
4. **Portable boot orchestration** — `hv-hypervisor-boot` (`no_std` + `alloc`) holds snapshot conversion, transfer boot, and VMX orchestration; `hv-hypervisor` re-exports for host tests.
5. **Requirements snapshot reserve fields** — `hypervisor_reserve_phys` / `hypervisor_reserve_bytes` bind static layout metadata into the embedded hypervisor image.

### SHOULD FIX (applied)

6. **UEFI `std` feature unification** — Hypervisor UEFI build uses path deps with `default-features = false`; embedded config is pre-generated by `tools/hv-config` into `build/hypervisor_embedded_config.rs`.
7. **Platform model `no_std`** — Runtime observe/validate paths compile without `std` for firmware consumers.
8. **Coverage and tests** — Added boot-abi transfer bounds tests, hypervisor-boot orchestration tests, VMX error/display coverage; workspace line coverage ≥ 95%.
9. **Documentation** — Architecture, platform contract, OVMF boot, and README updated for Phase 9 scope and deferred Gate C work.
10. **OVMF smoke alignment** — Smoke builds with `configs/ovmf-smoke.yaml`; QEMU memory/SMP match smoke config; serial evaluation requires successful chain-load without `Aborted`.

### Documented (deferred)

11. **Real VMXON/EPT/VT-d** — Mock backend only; hardware VMX enablement and EPT page tables remain Gate C.
12. **VT-d / interrupt remapping enablement** — Validated in requirements compare only; no IOMMU programming.
13. **Production PCI discovery** — Unchanged from Phase 8 (legacy port scan, no bridge recursion).
14. **Requirements snapshot metadata gaps** — `partition_id` / device `kind` strings still omitted; BDF + vm_id validation only.
15. **UEFI crates in workspace CI** — Standalone `*-efi-bin` manifests build via xtask/CI but remain outside root `cargo clippy --workspace`.
16. **OVMF smoke vs production requirements** — Smoke uses `configs/ovmf-smoke.yaml` (TCG-friendly); production `configs/qemu.yaml` Gate B + mock VMX init is host-tested.
